# AICheck 浏览器版图片检测站设计说明

> 这份设计草案基于 Gemini CLI 输出整理，用于把 AICheck 改造成“前端本地执行的 AI 图片检测网站”。

## 产品目标

- 做一个**AI 图片来源信号检测网站**，重点解决“这张图里有没有已知 AI 平台留下的来源痕迹”。
- 检测逻辑尽量放在浏览器本地执行，减少服务端成本和隐私风险。
- 输出必须可解释，告诉用户命中了什么信号，而不是只给一个神秘分数。

## 范围边界

- 当前站点只做**图片**，不做视频/音频。
- 当前浏览器版不是完整 CLI 等价移植，优先支持浏览器里可稳定运行的模块。
- 它是**来源信号检测器**，不是万能 AI 鉴定器。
- 只对**当前支持的平台/工具来源信号**负责，不对所有模型泛化承诺。

## 推荐架构

### 首选：纯前端 / 静态部署

- 网站：HTML + CSS + JS（可后续换 React / Vue）
- 核心检测：Rust -> WebAssembly
- 部署：GitHub Pages / Netlify / Vercel / 任意静态托管

优点：

- 文件不上传服务器
- 成本低
- 速度快
- 隐私更好

### 可选：补充后端

仅在需要这些能力时再加：

- 用户体系
- 检测历史
- 审计日志
- 任务队列
- 管理后台

## WASM 模块拆分建议

### Browser MVP

先支持这些浏览器内容易落地的图片信号：

- EXIF metadata
- XMP / IPTC metadata
- PNG 文本块
- 文件名启发式

### 后续增强

- C2PA 浏览器侧读取
- 可见水印检测
- 隐形水印检测
- Web Worker 并行分析

## 浏览器端文件流程

1. 用户选择图片
2. 前端读取为 `Uint8Array`
3. 把字节传给 WASM
4. WASM 返回结构化检测结果
5. 前端渲染信号、平台命中、风险提示

## UI 文案原则

首页要明确写：

- 只支持当前列出的平台/工具来源信号
- 不是万能 AI 鉴定器
- 未检测到信号 ≠ 一定不是 AI 图
- 图片只在本地浏览器处理
